## Why

Scientific papers arrive as PDF files, and `wiki add-source` refuses them today (`unsupported_file`). The human's workaround would be pasting text or using an agent's PDF reader, which bypasses capture and its provenance. A spike with pdfminer.six on a 67-page single-column preprint showed that a faithful markdown body is achievable: once the characters are rebuilt into visual lines, font, size and position separate body text, headings, figure captions, footnotes, references and page numbers.

## What Changes

- `wiki add-source <file>.pdf` captures single-column PDFs with a text layer:
  - characters are rebuilt into lines, and lines are classified by font, size and position;
  - the result is a markdown body with the title, `##` section headings, paragraphs rejoined across page breaks, `> Figure N: …` captions, `[^n]` footnote markers with `[^n]: …` definitions, and a numbered References list;
  - page numbers, running headers and footers are dropped.
- New raw frontmatter for PDF captures: `format: pdf`, `original_file` (the PDF copied under `raw/.orig/`), `original_sha256` and `original_size` of the PDF bytes, `extractor` with the pdfminer.six version, `pages`, and `doi` when page 1 prints one.
- Title from the largest text on page 1, falling back to the PDF's metadata title and then the filename. Authors from the PDF metadata or the line(s) between the title and the abstract, only when they look like names. `published` is never taken from the PDF's creation or modification dates.
- Refusals, with exit 2 and nothing written: `no_text_layer` (scanned PDFs), `multi_column` (two-column layouts, which are out of scope for now), `pdf_encrypted` and `pdf_unreadable`.
- Re-adding the same PDF bytes is a duplicate, even if the extracted text changed (because, for example, a newer extractor produced it).
- `wiki source-meta` re-derives a PDF capture's metadata from its stored PDF instead of treating it as HTML.
- The vault `.gitignore` template ignores `raw/.orig/*.pdf`: PDFs stay on the machine that captured them, and only the extracted text is committed. `wiki upgrade` brings the rule to existing vaults.
- `wiki lint` reports `original_not_local` (info) for a PDF capture whose stored PDF is absent, as it is on a fresh clone.
- `AGENTS.md` and the ingest workflow mention PDFs. Long sources are read section by section, and the References section is used to look up citations rather than summarised.
- New dependency: `pdfminer.six` (MIT, pure Python).

### Modified Capabilities
- `source-capture`:
  - adds a "Capture a PDF file" requirement;
  - duplicate detection also matches `original_sha256`;
  - `source-meta` handles PDF originals;
  - the `format` rule allows `format: pdf`.
- `wiki-lint`: the structural checks gain `original_not_local` (info).
- `vault-init`: the vault `.gitignore` ignores `raw/.orig/*.pdf`, and the schema and ingest workflow cover PDF sources.

## Impact

- **Code:**
  - new `src/llmwiki/pdf.py` (extraction and layout classification);
  - `sources.py` (dispatch, PDF capture, duplicate check, `derive_meta`);
  - `lint.py`;
  - the `cli.py` help text.
- **Templates:**
  - `templates/vault/dot-gitignore`, `templates/vault/AGENTS.md` and `templates/workflows/ingest.md`;
  - `templates/known_hashes.json` gains the new hashes, so `wiki upgrade` updates untouched vaults.
- **Dependencies:** `pdfminer.six` in `pyproject.toml`. It pulls in `charset-normalizer` and `cryptography`, both available as ready-built packages on macOS and Linux.
- **Tests:** synthetic PDFs are generated by a small writer in the test suite (standard Type 1 fonts, explicit positions and sizes), never from real papers.
- **Existing raw files and vaults:** existing raw files are unchanged. The `.gitignore` rule only affects PDFs captured from now on.
